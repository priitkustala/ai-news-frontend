## File names (sprint-02.md section 2.4)

Every scenario file is `tests/<journey>/<key>-<ac>-<suffix>-<short-name>.spec.ts`: `<journey>` is the row's journey tag without `@journey-`; `<key>` is the owning story's staged key (`S-<nn>`, or `40` for a bootstrap row); `<ac>` is the row's criterion (`AC-<nn>`, or `40` for a bootstrap row); `<suffix>` is the row's observation exactly as `coverage.md` writes it. A row whose observation is written `-` keeps that character as its suffix, so its file name carries three hyphens in a row, for example `tests/ingest/S-03-AC-04---keyword-relevance.spec.ts`; the rule is applied the same way in both repositories, in `coverage.md` and by `check_scenarios.py`. Each scenario's title starts with its row id (`AC-01a`, `AC-04`, `40a`), and its tags are exactly `@journey-<name>`, its one surface tag and `@story-<key>`. After the owner's approval the orchestrator replaces each staged key `S-<nn>` by its issue number (sprint-02.md section 5.2 step 4, `check_scenarios.py --remap`); `40` stays.

## Isolation and platform emulation (round 19 F6)

Each fixture set is a complete Given: `seed <set> <run>` resets the run records, the source configuration, the stored items and the bookmarks to the base seed plus that set, and its manifest echoes `fixture_set` and `run` (`support/job.ts` fails a scenario whose manifest does not). Because a seed resets shared state, scenarios run one at a time, by the configuration proposal staged in `e2e/pull-requests.md` (Configuration proposal: one worker), which this draft does not apply.

Notification permission and Web Push for AC-14a and AC-14b are emulated by `support/platform.ts`, before the page's own scripts run, in two separate states: granted (`Notification.permission` granted, the permission request resolves granted, the `pushManager` of a service worker registration resolves `subscribe()` with a subscription whose endpoint carries the run marker, whose `getKey('p256dh')` and `getKey('auth')` bytes agree with the base64url keys of its `toJSON()`, and which `getSubscription()` returns from then on) and refused (`Notification.permission` denied, the request resolves denied, `subscribe()` rejects with a `NotAllowedError`, `getSubscription()` returns none).
